## Средняя 4. Обновить запись

`UPDATE` одной записи с проверкой `rowcount`, массовое изменение цен по
условию и `INSERT … ON CONFLICT DO UPDATE`: поставка известного цветка
увеличивает остаток, неизвестный добавляется.

```
Новая цена лилии: True 270
Несуществующая запись: False
Подорожали на 10 %: 2 шт.
Поставка тюльпанов: (2, 150)
Новый цветок: (6, 20)
```

## Средняя 6. Параметры запроса

Знаки `?`, именованные параметры, необязательные условия
`(:low IS NULL OR price >= :low)`. Имя столбца параметром передать
нельзя, поэтому для сортировки оно выбирается из списка разрешённых.

```
Отклонено: сортировка по price; DROP TABLE flowers невозможна
```

## Повышенная 5. Транзакции

Перевод денег между счетами — два `UPDATE` и запись в журнал в одной
транзакции. При ошибке выполняется `ROLLBACK`, счета и журнал не
меняются. `pay_all` оборачивает каждый платёж в `SAVEPOINT`:
неудачные отменяются, остальные сохраняются. Тест проверяет, что другое
подключение не видит незавершённых изменений.

```
Начало:    {'Анна': 1000, 'Борис': 500, 'Вера': 0}
Перевод:   {'Анна': 700, 'Борис': 800, 'Вера': 0}
ROLLBACK:  NotEnough Вера: на счёте 0, нужно 50
ROLLBACK:  KeyError 'Глеб'
Без изменений: {'Анна': 700, 'Борис': 800, 'Вера': 0}
SAVEPOINT: не выполнены ['Глеб', 'Анна']
Итог:      {'Анна': 800, 'Борис': 500, 'Вера': 200}
```

## Повышенная 9. Асинхронный доступ (databases)

Запросы строятся объектами SQLAlchemy Core, выполняет их библиотека
`databases` с драйвером `aiosqlite`. Цены нескольких цветков
запрашиваются одновременно через `asyncio.gather`, продажа выполняется
в транзакции.
